# cargo-grid-visualizer

星际公民货舱的**手工装载编辑器**：选一艘船的网格（或自己填尺寸），逐层把箱子摆进去，
再导出成参考图，照着图在游戏里摆货。

和 `playground/cargo-pack/` 的分工：

| | cargo-pack | 本项目 |
| --- | --- | --- |
| 目的 | 求「填满且件数最少」的最优解 | 手工摆任意方案，并出图 |
| 输入 | 命令行 + 解包数据 | 浏览器界面 |
| 输出 | 终端方案 + SVG | 交互编辑 + PNG / SVG / JSON |

## 打开

双击 `index.html` 即可，不需要起服务、不需要 Node、没有第三方依赖。
`file://` 下会从 `ships.js` 读预设（用普通 `<script>` 而不是 `fetch`，所以不受 CORS 限制）。

> 如果 `ships.js` 缺失，应用仍然能用，只是没有预设船只，手动填 X×Y×Z 即可。

## 操作

| 操作 | 说明 |
| --- | --- |
| 左键 | 在光标处放一个当前箱型 |
| 右键 | 删掉光标下的箱子 |
| 拖动 | 移动已有箱子 |
| `R` | 没选中箱子时切换「放箱朝向」；选中时把该箱子转 90° |
| `1`–`7` | 选箱型（32 / 24 / 16 / 8 / 4 / 2 / 1 SCU） |
| `[` `]`、滚轮 | 切层（z 轴） |
| 方向键 | 微调选中的箱子 |
| `Del` | 删除选中的箱子 |
| `Ctrl+Z` / `Ctrl+Shift+Z` | 撤销 / 重做 |

- **落箱锚点**可切「居中」或「左下角」。居中时大箱子以光标为中心展开，更好对位。
- **层**是竖直方向（z）。2 格高的箱子在上一层会显示成**淡色虚线**，表示「这是下面那个箱子的上半截」，
  该位置不能再放东西。
- 高箱子在顶层放不下时会**自动下移**到能容纳的位置，光标行会提示。
- 每个箱型旁边的「已放 N」是当前网格里的件数。
- 方案自动存在浏览器 localStorage 里，换网格再切回来不会丢；也可以用「导出方案 / 导入方案」存成 JSON。

规则与 `docs/sc-cargo-grids.md` 一致：

- 1 格 = 1.25 m = 1 SCU，网格是长方体；
- 只允许绕竖直轴旋转 90°（宽长互换，高不变），不能侧放；
- **不做支撑校验**：可以悬空堆叠；
- 单件上限 `maxPermittedItemSize` 按排序后的三维比较（该字段轴序在容器间不一致），
  `0×0×0` 与 `1.25³` 视为「未设置」；
- 相邻货箱完全贴合，没有额外间隙。

## 导出

右栏选「图类型」和「范围」（当前网格 / 整船），然后 **PNG**（2×）或 **SVG**（文字不糊，可再编辑）。

| 图 | 内容 | 用途 |
| --- | --- | --- |
| 分层图（推荐） | 每个网格按 z 逐层俯视，箱子上标序号，下方是「序号 → SCU / 占格 / 层 / 坐标 / 是否旋转」清单 | 照着摆货 |
| 等距立体图 | 所有网格沿 X 并排的 3D 总览，**底部是横向排列的货箱统计**（每个尺寸几件，没放的不显示；一行放不下自动换行），没有标题 / 网格名 | 看整体形状 |
| 三视图 | F（X-Z）/ S（Y-Z）/ T（X-Y） | 对照舱内轮廓 |

三视图是**从外侧看**的投影，只显示最外一层可见的箱子；内部结构看分层图。

分层图的清单是固定宽度的等宽字体表：`#` 是序号，`layer` 是 `z0-1` 这种层区间，
`(x,y)` 是箱子最小角的格坐标，`rot` 为 `y` 表示宽长互换过。

## 字号

导出图里所有文字的大小由一个倍率控制，在 `js/render.js` 顶部：

```js
var FS = 1.5;   // 字号倍率：1.0 = 原来的基准，1.5 = 放大 50%
```

行高、表格列宽、卡片尺寸、标签偏移这些跟着文字走的间距都按同一个倍率算，
所以改完不会出现文字压在一起。编辑画布里的坐标刻度和箱子编号也跟着变。

界面（左中右三栏的 HTML/CSS）不在这个倍率里，用的是桌面常规字号。

## 配色

**全部在 `js/theme.js`**，改完刷新即可：

- `crateColors` —— 货箱颜色（键是 SCU 数），界面和导出图共用；
- `sheet` —— 导出图的浅色配色；
- `editor` —— 编辑画布；
- `ui` —— 界面外壳，启动时写进 CSS 变量；
- `iso` —— 等距图各面的明暗系数。

`index.html` 里 `:root` 的那几个变量只是兜底值，会被 `theme.js` 覆盖，不用改那里。

## 预设数据

`ships.js` 由 `tools/gen_ships.py` 从 SDE 生成，数据源是
`playground/scrape-lab/data/sde/ships.json`（已按默认装配解析过 `CargoGrids`），
**不需要解包数据或 starbreaker**。

```bash
python3 tools/gen_ships.py            # 覆盖 ships.js
python3 tools/gen_ships.py --src <ships.json> --out <输出路径>
```

当前结果：331 条记录里 **157 艘有货舱网格，共 538 个网格**，生成文件约 51 KB。
脚本会做四件事：米换格、折掉单件上限哨兵值、把网格名裁成 `Cargo_Main` 这种短名、
丢掉 `35×35×35` 开发占位模板。

## 已知限制

1. **SDE 只覆盖 157/331 艘**：模块化货舱没接进默认装配的船（部分模块舱）会缺网格，
   这类船在列表里看不到对应舱位，用「自定义 X×Y×Z」手填。
2. **竖直轴是假设**：数据里没有写网格的 up 轴，这里统一按 Z 处理。
   实测 Zeus / 毛虫 / Carrack 的尺寸关系支持这个假设，但没有逐船核对。
3. **单件上限的轴序**：见上，比较时按排序三维，摆放仍然只允许 yaw。
4. **不做自动求解**：`cargo-pack` 有精确解和贪心填充，本项目只管手工摆放；
   需要「最少件数」的答案去那边算。
5. **整船导出会把空网格也画出来**（只有地面 + 标签），方便确认哪些舱还没装。

## 测试

```bash
.venv/bin/pytest               # tools/gen_ships.py 的解析规则（覆盖率门槛 70%）
node tests/js/test_geometry.js # 前端坐标换算 + 摆放规则 + 出图
```

前端是零依赖的普通 script，所以 `tests/js/` 用 node 直接跑，不引入测试框架。
它守住两个曾经踩过的坑：画布坐标换算把 `devicePixelRatio` 乘进去（高 DPI 屏上
预览偏向右下、严重时直接飞出网格），以及 SVG 的 `font-family` 引号嵌套。

界面本身没有自动化测试，改动后建议按下面的自查清单过一遍：

0. 把系统缩放调到 125% / 150% 再看一遍 —— 鼠标落点和货箱预览必须严格对齐；
1. 选 `RSI Zeus Mk II CL` → `Cargo_Main`，显示 5×8×3 = 120 SCU，32 SCU 可用；
2. 在 z=0 放两个 32 SCU（2×2×8，占满 x=0..3），切到 z=1 应显示为淡色虚线；
3. 在 z=2 用 4 SCU 铺满，统计应到 120/120、22 件（与 cargo-pack 的最优解一致）；
4. 导出分层图，序号 1–22 与清单坐标能对上；
5. 同一方案导出的 PNG 与 SVG 几何一致。
